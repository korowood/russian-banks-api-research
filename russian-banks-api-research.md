## 2. API / программный доступ по банкам

Легенда статусов:
- **есть** — есть документированный публичный API по сути категории (portal/docs, можно интегрировать);
- **частично** — только кусок категории, либо терминал/H2H/пилот/partner без полного self-serve API;
- **не найдено публично** — в открытых источниках подтверждения нет.

### 2.1. Сбербанк

**Порталы:** [Sber API overview](https://developers.sber.ru/docs/ru/sber-api/start/overview), [продуктовая страница](https://developers.sber.ru/portal/products/sber-api), [SberCIB Terminal](https://www.sberbank.ru/ru/legal/investments/globalmarkets/voperations)

**Модель доступа (важно):** Sber API продаётся **наборами**, ЛК живёт внутри **СберБизнес**:
| Набор | Для кого | Что внутри (кратко) |
|-------|----------|---------------------|
| **Компаниям** (бывш. Host2Host) | одна организация | платежи, выписки, депозиты/НСО, ВЭД, СБП, карты, эквайринг… |
| **Холдингам** | группа компаний | платежи/выписки/депозиты/ВЭД по дочерним (отдельные токены) |
| **Платформам** (бывш. B2BSaaS) | сервис поверх клиентов банка | платежи/выписки/СБП от имени клиентов платформы |
| **СберБизнес ID** | SSO | авторизация клиентов на сайте партнёра |
| **Кредит в корзине** | B2B-покупки в кредит | credit offers |

| Категория | Статус | Тип доступа | Документация / детали | Ограничения |
|-----------|--------|-------------|----------------------|-------------|
| **FX spot** | **есть*** | Sber API: поручения на покупку/продажу валюты (`CONVERSION_OPERATION_CURRENCY`) | [Conv currency](https://developers.sber.ru/docs/ru/sber-api/scenarios/ved/conv-currency/overview) | *Корп. конверсия, не CIB trading Terminal. Набор «Компаниям»; СберБизнес ID |
| **Brokerage (repo, bonds…)** | **не найдено публично** | — | Публичного Invest API (аналог T-Invest) **нет** | — |
| **Депозиты / FX swap / forward** | **частично** | **Депозиты+НСО = есть** в Sber API; **SWAP/FWD/NDF** — SberCIB Terminal (UI + заявленное API без публичной OpenAPI-спеки) | [Депозиты](https://developers.sber.ru/docs/ru/sber-api/scenarios/placement/deposit/overview) | Депозиты RUB/CNY/INR; sandbox есть |
| **Credits + rates (cap/floor)** | **частично** | «Кредит в корзине» / `GET_CREDIT_OFFERS`; **cap/floor treasury API нет** | [Credit offers](https://developers.sber.ru/docs/ru/sber-api/specifications/credit-offers/get-credit-offers) | Партнёрский набор |
| **Transactions** | **есть** | наборы Компаниям / Холдингам / Платформам | [Платежи](https://developers.sber.ru/docs/ru/sber-api/scenarios/transfers/payments/overview), [Выписки](https://developers.sber.ru/docs/ru/sber-api/scenarios/rko/statements/overview) | Клиент/пользователь **СберБизнес**; ЭП; scope в договоре |
| **Прочее** | **есть** | portal + тестовый стенд | ВЭД, карты, эквайринг, самозанятые, инкассация, СБП | Юрлица/ИП РФ |

### 5.2.1. H2H (Host-to-Host) — подробно

**Что это.** Канал, где **сервер компании** (1С, SAP, Oracle, своя ERP) напрямую обменивается сообщениями с **сервером банка**. Бухгалтер не заходит в интернет-банк, не копирует платёжки руками: платёж создаётся в учётной системе и уходит в банк как электронное поручение; выписка приходит обратно в ту же систему.

**Пример.** Завод каждый день платит 200 поставщикам. Без H2H: казначей выгружает реестр из 1С → заходит в Клиент-Банк → загружает файл → подписывает → ждёт статусы → вручную разносит выписку. С H2H: в 1С нажали «Отправить в банк» → XML/ISO 20022 ушёл по защищённому каналу (часто VPN + сертификаты) → банк принял, вернул статусы → ночная выписка сама легла в 1С и закрыла платежи. У ВТБ это называется ИБК, у ГПБ/Альфы/ПСБ — продукты Host-to-Host / DirectBank.

**Плюсы**
- Меньше ручного труда и ошибок при больших объёмах платежей.
- Быстрее цикл «создал → отправил → увидел статус».
- Выписки и статусы сразу в ERP — проще сверка и закрытие дня.
- Можно автоматизировать зарплату, массовые выплаты, ВЭД-поручения (если банк это отдаёт в H2H).

**Минусы**
- Долгое подключение: договор, анкеты, тест, согласование форматов — часто недели/месяцы, не «зарегистрировался на portal за день».
- Обычно только для среднего/крупного бизнеса с расчётным счётом в этом банке.
- Форматы банка-специфичны (свой XML/ISO-профиль) — мультибанк = несколько интеграций.
- Безопасность на стороне клиента: ключи ЭП, сертификаты, VPN, контроль доступов в ERP.

**Сложности на практике**
1. **Согласование формата** — поля платёжки, кодировки, справочники статусов у каждого банка свои оттенки, даже при «ISO 20022».
2. **Электронная подпись и роли** — кто в ERP имеет право подписывать, как хранить ключи, что делать при смене подписанта.
3. **Идемпотентность и ошибки** — повторная отправка той же платёжки, таймауты, частичный приём реестра.
4. **Тестовый контур** — не у всех банков удобный sandbox; иногда тест только на копии боевого канала.
5. **Сопровождение** — банк меняет схему/сертификат, у клиента падает обмен, пока не обновят адаптер.
6. **Не путать с Open API** — H2H часто закрытый B2B-канал; публичного developer portal может не быть, хотя платежи «через API» уже идут.


### 5.3. Продуктовые / treasury / рынок

| Термин | Что значит |
|--------|------------|
| **FX** | Foreign Exchange — валютный рынок / валютные операции. |
| **FX spot** | Сделка купить/продать валюту с расчётом «почти сразу» (обычно T+0…T+2). |
| **Корп. conv API / корп. конверсия** | API для **корпоративной** покупки/продажи валюты со счетов компании (поручение банку). Это не полноценный торговый терминал маркет-мейкера. У Сбера — метод `conv-currency`. |
| **CIB** | Corporate Investment Banking — инвестбанковский/казначейский блок для крупного бизнеса и финансовых институтов. |
| **SberCIB Terminal** | Торговый терминал Сбера для FX и срочных сделок (SPOT/SWAP/FWD и др.); API для него заявляется, но публичной OpenAPI-спеки как у Sber API нет. |
| **eFX** | Electronic FX — электронная FX-платформа банка (у ВТБ: терминал + ценовой поток). |
| **STP** | Straight-Through Processing — автоматическая прогрузка сделок из терминала во внутренние системы клиента без ручного ввода. |
| **TOD / TOM / SPOT** | Валютирование: сегодня / завтра / стандартный спот (обычно T+2). |
| **SWAP (FX swap)** | Две связанные валютные сделки: обмен сейчас и обратный обмен позже. |
| **Forward / FWD** | Форвард: курс фиксируется сейчас, расчёт в будущем. |
| **NDF** | Non-Deliverable Forward — расчётный форвард без поставки валюты (разница в деньгах). |
| **OTC** | Over-the-Counter — сделка напрямую с банком, не на бирже. |
| **Brokerage / Invest API** | API брокерского счёта: бумаги, заявки, котировки (акции, облигации, валюта на бирже). |
| **Repo** | Сделка РЕПО: продажа ценной бумаги с обязательством обратного выкупа (по сути обеспеченный займ). |
| **Bonds / облигации** | Долговые бумаги (в т.ч. гособлигации). |
| **НСО** | Неснижаемый остаток — договор: на счёте держите минимум X денег, банк платит повышенный процент. Не путать с депозитом «заморозкой» на отдельном счёте. |
| **Овернайт** | Размещение денег «на одну ночь» (сверхкороткий депозит/размещение). |
| **Credits + rates** | Кредитные продукты и ставки. |
| **Cap / floor** | Опционы на ставку: потолок (cap) и пол (floor) процентной ставки — treasury-инструменты; в публичных API банков РФ **не найдены**. |
| **Credit-in-cart / «Кредит в корзине»** | Сценарий: компания на сайте партнёра оплачивает покупку кредитом банка (B2B), не «казначейский» кредит с cap/floor. |
| **Treasury** | Казначейство: управление ликвидностью, FX, ставками, размещениями для крупного бизнеса. |
| **Transactions** | Операции по счетам: платежи, выписки, статусы, переводы. |
| **ПП** | Платёжное поручение. |
| **СБП** | Система быстрых платежей. |
| **ВЭД** | Внешнеэкономическая деятельность (валютные контракты, валютный контроль). |
| **Эквайринг** | Приём оплаты картами/онлайн на стороне продавца. |
| **Номинальный счёт** | Счёт, где деньги учитываются для бенефициаров (маркетплейсы, эскроу-подобные схемы). |
| **Open Banking / ОБИ** | Стандарты обмена банковскими данными с согласием клиента (в РФ — через АФТ/ЦБ, часто пилоты). |
| **АФТ** | Ассоциация ФинТех. |
| **ЦБ** | Банк России (регулятор). |
| **Self-serve portal** | Публичный кабинет разработчика «зарегистрировался и поехал». |
| **Пилот** | Ограниченный запуск стандарта/API не для всего рынка. |

### 5.4. Примеры «как читать» короткие пометки в матрице

| В матрице написано | Расшифровка |
|--------------------|-------------|
| **корп. conv API** | Есть API корпоративной конверсии валюты (поручение банку), не биржевой робот. |
| **не CIB Terminal** | Это не торговый терминал SberCIB; отдельный канал. |
| **eFX + STP** | Электронная FX-платформа ВТБ + автовыгрузка сделок в системы клиента. |
| **H2H ISO20022** | Прямой канал Host-to-Host по стандарту ISO 20022. |
| **депозиты/НСО ✅** | Депозиты и неснижаемый остаток в Open API есть. |
| **swap/fwd только CIB** | Валютный своп/форвард — через казначейский терминал, не через обычный Sber API. |
| **credit-in-cart** | Кредит на оплату покупки у партнёра, не полный кредитный treasury API. |
| **T-Invest (bonds+)** | Брокерский API Т-Инвестиций: облигации и другие инструменты. |
| **PRO API** | API торгового терминала Альфа-Инвестиции PRO. |
